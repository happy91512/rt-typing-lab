# RT 打字實驗室

用英文、繁中與實體鍵短測比較磁軸鍵盤的 Rapid Trigger（RT）設定，找出值得調整的鍵位。打字測試只需瀏覽器與鍵盤，進度儲存在目前瀏覽器。

## 在本機啟動

使用 Node.js 24 以上版本。下載專案後，在專案目錄執行以下指令，並開啟終端機顯示的網址。

```sh
npm ci
npm run dev
```

## 比較 A 與 B 組設定

1. 在**目前設定**填入官方驅動中使用的槽位、RT 欄位、刻度與逐鍵例外值。保持 A 組原設定，完成**基準測試**。
2. 選擇最多六個要測的鍵，設定 B 組候選值，再按**開始三對比較**。
3. 每組開始前，依網頁清單在官方驅動手動套用設定，再回到網頁確認。依 A、B，B、A，A、B 的順序測試。兩組的首次觸發、死區和本次未測的 RT 欄位請使用相同設定。若你的驅動可分開保存板載槽位，可將原值留在 A 槽並使用另一槽測候選值。
4. 在**逐鍵結果**查看樣本與實測推薦。按**用新文本複測整組**，檢查推薦值合用時的中英文速度與錯字率。按**下載 CSV**保存結果。想切回原設定時，展開**還原測試前的設定**。

點選鍵盤圖上的鍵，可以展開該鍵的比較紀錄。若網頁找到值得再試的相鄰值，可以直接將它加入下一輪。新候選值通過比較前，目前的實測推薦仍然有效。

同一對 A/B 使用相同題目，後續的對照題會更換文本及單按、連按的排列。重新整理後，當前這一對仍使用原本的題目。

想多收集數字或符號的資料，可在**基準測試**或**逐鍵結果**選**補測低樣本鍵**。切回 A 原設定後完成短題。補測會增加基準樣本，有需要時仍可做 A/B 驗證。

有實測推薦時，可在**官方驅動套用清單**查看或下載 A 原設定與 B 套用值。清單也列出先前試過、應恢復 A 值的鍵，並標明整組複測狀態。

RT 設定全部由你在官方驅動手動套用。網頁不會自動寫入鍵盤設定。

## 鍵程量測

在**基準測試**展開**即時行程（實驗）**。如果瀏覽器在 HTTPS 或 localhost 提供 WebHID，選擇鍵位並按**連線並量測**，再授權連線至 HERO 84 HE ANSI。已有一把實體鍵盤回報即時行程，短題所需的回報速度仍在驗證。無法量測時，仍可完成打字比較。

在量測區以不同速度按下和放開選定鍵至少五次。畫面會顯示原始讀值、回報間隔和成功對齊的事件數。展開**用行程試算 RT 候選值**，核對驅動刻度、首次觸發點、死區與軸體行程，再做單按和連按短題。當回報速度足夠且試算能重現原設定的觸發，才會提出待驗證的候選值。逐鍵推薦仍由 A/B 測試產生。按**結束量測**後再切回官方驅動。

只想知道取樣速度時，按**測試取樣速度（4 秒）**並連續按下和放開選定鍵。保留目前 RT 開關和設定即可。
